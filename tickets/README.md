## 番号と実装順がずれている理由

**TICKET-016（GCP ブートストラップ）は最後に起票されたが、004 より先に実施します。**

004（Terraform）と 005（CI/CD）は当初「GCP プロジェクトが既にある」ことを暗黙に
前提していましたが、それを作るチケットが存在しませんでした。ゼロから立ち上げる方針を
確定したため、016 を追加して依存の先頭に置いています。

## 着手の起点

**003 と 016 は互いに独立しているので、どちらから始めても構いません。**

- 003（認証基盤）はローカルの Firebase Auth エミュレータで完結するため、
  本物の GCP プロジェクトが無くても進められます
- 016（GCP ブートストラップ）は手作業とコンソール操作が中心で、コードの依存がありません

クラウドに出す予定が近いなら 016 を先に、アプリの実装を進めたいなら 003 を先に。

## 鶏と卵になっている箇所

| 箇所 | 内容 | 解消方法 |
|---|---|---|
| tfstate | Terraform は自分の state 置き場を同じ apply では作れない | **016** で GCS バケットを先に作る |
| WIF | CI から Terraform を動かすには WIF が要るが、WIF を作るのも Terraform | **初回だけ手元の ADC で apply**（005） |
| Firestore | コンソールで作るとリージョンと PITR が Terraform 管理外になる | **016 では作らず 004 の Terraform で作る** |
