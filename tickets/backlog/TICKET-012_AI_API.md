## 概要

Claude API を中継する AI エンドポイントを実装する。解説生成・タグ提案・問題生成の
3種類と、プロンプトテンプレートの管理（編集と変更履歴）、レート制限を含む。

## 背景・目的

API キーをブラウザに置けないため、サーバが中継する必要がある。
また Claude の出力は信頼できない入力であり、**検証してから保存する**経路を最初から作らないと
壊れたデータが混入する。従量課金のためレート制限も必須。

## 受け入れ条件

- [ ] `api/openapi.yaml` に AI エンドポイントが定義され、生成物がコミットされている
- [ ] 解説生成・タグ提案・問題生成の3種類が動く
- [ ] **応答は同期 REST**（ストリーミングを使わない）で、パース済みの構造化データを返す
- [ ] **Claude の出力 JSON を検証してから返す。** パース失敗・スキーマ不一致は **502** を返し、
      **Firestore には何も書かない**
- [ ] モデルIDが環境変数 `CLAUDE_MODEL`（既定 `claude-sonnet-5`）で指定され、ハードコードされていない
- [ ] `ANTHROPIC_API_KEY` が Secret Manager 経由で注入され、**レスポンス・ログに現れない**
- [ ] レート制限が `/usage/{uid}` のカウンタで実装され、超過時に **429 と `Retry-After`** を返す
- [ ] レート制限が**インスタンス数に依存しない**（メモリ上のカウンタではない）
- [ ] プロンプトテンプレートの取得・更新ができ、更新時に旧版が
      `/prompts/{promptId}/revisions/{revId}` に残る
- [ ] 過去のリビジョンへロールバックできる
- [ ] ユーザ入力がシステム指示を上書きできない構造になっている
- [ ] **`claudeapi` がインターフェース越しにモックされ、Claude API を実際に叩く自動テストが存在しない**
- [ ] ユースケース層のユニットテスト（モック使用）がある
